# DORA 低显存复现：项目结项报告

## 项目状态

本项目已于 2026 年 8 月完成阶段性收尾。仓库进入维护状态：保留可复现代码、脱敏汇总和验收脚本，不再围绕小预算取整继续扩展实验。

本项目是对 DORA 的独立低显存复现，不代表原论文作者或官方实现。它没有完成论文规模的准确率复现，也没有提出经过充分验证的新算法。

## 完成内容

1. 在单张 RTX 4070 Laptop 8 GB 上运行 Qwen2.5-1.5B Policy、Qwen2.5-Math-PRM-7B 和 BGE-M3。
2. 将三个模型拆为分时进程，以 JSONL 传递中间结果，峰值显存控制在 4.43 GiB。
3. 实现并验收三轮“部分生成—PRM评分—BGE方向估计—预算重分配—路径续写”。
4. 在40条冻结候选上验证4-bit PRM与混合BF16的排序和分配高度一致。
5. 修复最终答案解析，区分解析失败、推理错误和生成截断。
6. 以12万轮CPU模拟研究小预算整数化，并用真实PRM/BGE轨迹重放三种分配方法。
7. 完成三种整数分配方法各20题的端到端探索实验和配对统计。
8. 建立日志、配置、环境快照、自动验收、脱敏公开结果和独立Git版本管理。

## 最终证据

| 结论 | 证据 |
|---|---:|
| 4-bit PRM峰值显存 | 4.43 GiB |
| 4-bit/BF16 Spearman | 0.9883 |
| 4-bit/BF16 Top-1及整数分配一致 | 100% |
| 答案提取在既有40条标注上的一致 | 40/40 |
| D2官方独立取整原始预算违规 | 13/60 |
| D2 pass@4：官方/最大余数/累计 | 15/20、16/20、16/20 |
| D2多数答案正确率 | 三种方法均13/20 |

真实实验支持：小预算下，官方独立取整可能不守恒，后续补齐会改变候选覆盖；预算守恒方法能够改变搜索路径。但20题结果没有证明这种变化能提高最终提交答案的正确率。

## 最终结论

可以声称：

- DORA核心搜索机制可以在8 GB消费级GPU上以模型分时方式运行；
- 当前样本中4-bit PRM足以保持候选排序和整数分配；
- 预算4时，独立取整和补齐是一个真实、可测量的搜索实现边界；
- 项目形成了可复查的工程复现和诚实的负结果。

不能声称：

- 完整复现论文的MATH-500或AIME结果；
- DORA在本项目设置中优于基线；
- 最大余数或跨轮累计提高最终准确率；
- 预算4的现象可以外推到论文使用的16–256 rollout；
- 已形成可独立投稿的新算法成果。

## 停止继续扩展的理由

现有证据已经解释了预算4的主要取整现象。继续扫描预算、步长和温度，主要增加适用边界数据，但在1.5B Policy、20题和单卡条件下很难形成非平凡的新结构或可靠的性能结论。因此本项目在此收束，不用更多小样本调参包装研究贡献。

如果未来获得稳定算力和明确研究问题，可从论文尺度重新启动：使用更大Policy、16–64以上预算、100–500题、多随机种子和正式基线；这应作为新的实验阶段，而不是当前结论的自然外推。
