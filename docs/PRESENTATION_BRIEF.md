# DORA 低显存复现：一页摘要

## 一句话介绍

我在单张 RTX 4070 Laptop 8 GB 上完成了 DORA 核心搜索机制的低显存复现，并验证了4-bit 7B PRM的排序保真度以及小预算整数分配的真实影响。

## 为什么做

DORA 原始实验依赖 A100 集群。我的目标不是立即复跑全部论文表格，而是先验证：有限硬件上能否真实运行逐步资源分配，以及量化 PRM 是否仍能提供可靠的搜索指导。

## 我完成了什么

- 将 Policy、PRM、BGE 拆成 JSONL 交接的分时流水线；
- 把 7B PRM 以 4-bit NF4 部署，峰值显存约 4.43 GiB；
- 实现三轮部分路径生成、逐步评分、语义多样性和动态预算分配；
- 修复最终答案提取，将截断与推理错误分开统计；
- 在相同 40 条候选上完成 4-bit 与混合 BF16 对照；
- 完成12万轮CPU整数化模拟、真实PRM/BGE轨迹重放和三种方法各20题的端到端探索；
- 建立验收脚本、运行日志、环境快照和独立版本管理。

## 最重要的数字

| 项目 | 数值 |
|---|---:|
| 4-bit PRM 峰值显存 | 4.43 GiB |
| 4-bit / BF16 Spearman | 0.9883 |
| Top-1 一致率 | 100% |
| 整数分配一致率 | 100% |
| 答案抽取样本内一致率 | 40/40 |
| 非均匀动态分配轮数 | 2/3 |
| 官方独立取整原始预算违规 | 13/60 |
| pass@4（官方/最大余数/累计） | 15/20、16/20、16/20 |
| 多数答案正确率 | 三种方法均13/20 |

## 研究观察

在预算4时，官方独立取整经常不能保持预算，补齐策略会改变候选覆盖；最大余数和累计方法确实改变搜索路径，但没有观察到多数答案正确率提升。这说明它是一个真实的低预算实现边界，而不是已经成立的算法改进。

## 对结果的诚实边界

当前完成的是工程可行性、机制验收和20题探索性负结果。项目没有完成MATH-500全量复现，不能证明DORA优于基线，也不能证明整数分配改动提高准确率。

## 项目状态

项目已阶段性结项并进入维护状态，不再继续小样本预算、步长和温度扫描。若未来获得稳定算力，应把更大Policy、16–64以上预算、100–500题、多随机种子和正式基线作为新的研究阶段。
