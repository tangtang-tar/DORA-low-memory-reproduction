# DORA 低显存复现：一页摘要

## 一句话介绍

我在单张 RTX 4070 Laptop 8 GB 上完成了 DORA 核心搜索机制的低显存复现，并验证了 4-bit 7B PRM 对候选排序和资源分配的保真度。

## 为什么做

DORA 原始实验依赖 A100 集群。我的目标不是立即复跑全部论文表格，而是先验证：有限硬件上能否真实运行逐步资源分配，以及量化 PRM 是否仍能提供可靠的搜索指导。

## 我完成了什么

- 将 Policy、PRM、BGE 拆成 JSONL 交接的分时流水线；
- 把 7B PRM 以 4-bit NF4 部署，峰值显存约 4.43 GiB；
- 实现三轮部分路径生成、逐步评分、语义多样性和动态预算分配；
- 修复最终答案提取，将截断与推理错误分开统计；
- 在相同 40 条候选上完成 4-bit 与混合 BF16 对照；
- 建立验收脚本、运行日志、环境快照和独立版本管理。

## 最重要的数字

| 项目 | 数值 |
|---|---:|
| 4-bit PRM 峰值显存 | 4.43 GiB |
| 4-bit / BF16 Spearman | 0.9883 |
| Top-1 一致率 | 100% |
| 整数分配一致率 | 100% |
| 答案抽取样本内一致率 | 40/40 |
| 非均匀动态分配轮数 | 2/3 |

## 研究观察

在 rollout 总预算很小时，BGE 产生的连续多样性差异会被整数舍入消除；同时，接近饱和的 PRM 分数可能压倒多样性项。这提示可以研究跨轮累计分配或基于分数熵的自适应温度。

## 对结果的诚实边界

当前完成的是工程可行性和机制验收。5题初步对照中各方法均为2/5，尚不能证明DORA优于基线，也没有完成MATH-500全量复现。

## 下一步设想

优先在本地完成答案解析留出集、小预算累计分配和失败案例分析；在获得更多算力后，再运行MATH-500上的DORA、REBASE和基础采样对照。
